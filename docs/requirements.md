# 求职数据仪表盘 · 需求定义 v0.1

> 来源：lio 个人发展路线图 · 里程碑2（2026-08-05 定稿）
> 目标：把 31k+ 条自动化投递记录变成"能看懂、能讲故事"的数据产品——既是求职决策工具，也是作品集项目。

## 1. 背景与目标

- 现状：`job-hunter` 自动化投递已累计 31,214 条记录（boss 31,201 / 51job 13），落在 `jobintel/data/jobintel.db`，无人问津
- 痛点：投了 1 万+ 份 0 offer，**没有反馈闭环**——不知道投递结构、趋势、分布，无法判断"方向对不对"
- 目标：一眼看清自己投了什么、投到哪、结果如何，用数据代替感觉做决策
- 副产品：一个可上 GitHub 的作品集项目（FastAPI + 原生前端 + SQLite，与 llm-arena 同款技术栈）

## 2. 数据源（只读，不改）

| 字段 | 说明 |
|---|---|
| source | boss / 51job |
| status | applied / skipped / failed |
| city / company / job / keyword | 城市 / 公司 / 岗位 / 投递关键词 |
| salary_raw, salary_min_k, salary_max_k, salary_unit, salary_months | 薪资（单位：K / 万 / 元/月 / 元/天） |
| score, reason, error | 匹配分 / 跳过原因 / 错误 |
| ts | ISO 时间（约 3 万条非空） |

## 3. 页面清单（3 页）

### 3.1 总览页 `/`
- KPI 卡：总投递 / 已投 / 跳过 / 失败
- 状态分布（环形图）
- 来源分布（条形）
- 城市 Top10（条形）
- 关键词 Top10（条形）
- 薪资分布（直方图，归一化为月薪 K）
- 近 7 天投递（折线）

### 3.2 趋势页 `/trend`
- 按天投递量折线：boss / 51job / applied 三条线（默认 30 天）

### 3.3 明细页 `/detail`
- 表格：时间 / 来源 / 状态 / 城市 / 公司 / 岗位 / 薪资 / 分 / 关键词 / 原因
- 筛选：城市 / 来源 / 状态 / 关键词模糊搜索
- 分页

## 4. API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/overview | 总览全部聚合 |
| GET | /api/trend?days=30 | 按天趋势 |
| GET | /api/detail?page=&city=&source=&status=&kw= | 分页明细 |

## 5. 非功能要求

- 零构建原生前端（与 llm-arena 一致，无 CDN 离线可用）
- 只读数据库：任何写入都发生在 job-hunter 侧，仪表盘永远不改数据
- 安全：纯本地；暴露公网时需加鉴权（复用 llm-arena 的 LLM_ARENA_ADMIN_TOKEN 模式）
- 图表用自写 SVG 渲染（不引第三方图表库）
